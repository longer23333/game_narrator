# 素材库检索与标签设计

## 设计依据

本模块借鉴公开项目和官方接口的“元数据聚合”思路，但 Java 业务代码为本项目独立实现：

- Wikimedia Commons 搜索同时返回文件、许可与作者元数据，因此中文请求先转换为紧凑英文检索词。
- 来源标签映射为 `SOURCE`、`PLATFORM`、`AI`、`QUERY`，用户修正仍具有最高优先级。
- Ollama 官方生成接口：本地模型使用 JSON 结构化结果生成英文检索词和中文标准标签。
- Freesound API：后续音效适配器保留平台标签和内容分析字段。

## 中文检索流程

```text
中文搜索词
→ 本地词典保底扩展
→ Ollama 生成英文检索词与中文标准标签
→ Wikimedia Commons 检索文件与许可元数据
→ 保存原始标签
→ AI 二次分类
→ 用户修正标签
```

Ollama 不可用时仍使用内置游戏/动漫剪辑词典，不会导致中文搜索完全失效。

## 标签优先级

```text
用户 REMOVE
> 用户 ADD
> 平台/素材库原始标签
> 搜索意图标签
> AI 推断标签
```

用户操作不删除原始数据，而是写入覆盖表。因此系统可以保留来源事实，同时在后续素材匹配中采用用户确认后的有效标签。

## 平台内容边界

对于 Bilibili、YouTube、抖音和 TikTok：

- 可登记用户本人拥有或已获授权的素材链接、标签与许可声明。
- 只通过平台官方 API 或明确允许的下载地址获取文件。
- 不通过解析页面、绕过签名或规避访问控制下载媒体。
- 未声明许可的引用默认只作为灵感和索引，不自动进入最终成片。

## 来源收敛与历史兼容

- 新的开放许可图片、Meme、音频与可自动使用的视频检索统一走 Wikimedia Commons。
- Bilibili 仅作为显式选择的视频候选来源，必须完成权利确认，不参加自动素材放置。
- Openverse、Pexels、Pixabay 的新搜索与密钥配置入口已经移除；数据库迁移和既有 `external_asset` 记录不删除，历史素材仍可查看、筛选和按原许可使用。

## 远程素材断点续传

- 自动下载在后台任务执行，页面通过 `/api/assets/{id}/download-status` 显示队列、字节数、百分比与失败原因，不再让单个 HTTP 请求阻塞到文件下载结束。
- 未完成内容写入素材专属目录的 `source.<ext>.part`；失败状态为 `PARTIAL`，再次点击会使用已保存的 ETag/Last-Modified 和 `Range` 从现有字节继续。
- 服务端忽略 Range 并返回完整 `200` 时，临时文件会先截断再重下；返回不匹配的 `Content-Range` 时拒绝拼接。
- 收到的字节数必须与远程总大小一致且不超过 100 MB，完成后才原子替换正式文件并标记 `DOWNLOADED`。
- `.part` 文件只位于受管 `storage-root/library/{assetId}` 内，SSRF、公网 HTTPS 和许可白名单检查继续生效。

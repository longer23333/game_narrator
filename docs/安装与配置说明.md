# GameNarrator 安装与配置说明

本文适用于从仓库检出的源码，以及由 `scripts\package-source-release.py` 生成的源码发行包（文件名形如 `GameNarrator-Source-<版本>.zip`）。本文讲的是开发与运行配置；最终用户请直接使用 Windows 安装包 `GameNarrator-Setup-<版本>.exe`，打包与校验流程见 `docs/RELEASE_PROCESS.md`。项目包含 Spring Boot 后端、Vue Web 前端、Windows 启动器、Android 客户端和浏览器扩展。

## 1. 推荐目录

建议把源码、模型和用户数据放到非系统盘，例如：

```text
G:\GameNarrator\source      源代码
G:\GameNarrator\models      Ollama、Whisper、Piper 模型
G:\GameNarrator\storage     项目视频与中间产物
G:\GameNarrator\data        数据库与配置
```

路径应避免中文特殊符号和过长层级。不要把模型、视频和构建缓存放到 C 盘。

## 2. 开发环境

- Windows 10/11 64 位
- Java 21
- Node.js 20 或更高版本
- .NET 8 SDK（构建 Windows 启动器时需要）
- Android Studio及Android SDK（构建Android客户端时需要）
- FFmpeg、Ollama、whisper.cpp、Piper（执行完整AI视频流程时需要）
- PostgreSQL 15或更高版本（生产模式可选；本地开发可使用H2）

运行以下命令检查基础环境：

```powershell
java -version
node --version
npm --version
dotnet --info
```

## 3. 后端启动

在源码根目录执行：

```powershell
.\mvnw.cmd spring-boot:run
```

默认访问地址为 `http://127.0.0.1:8081`（可用环境变量 `SERVER_PORT` 覆盖）。第一次启动会创建本地数据库和存储目录，并执行Flyway迁移。

生产构建：

```powershell
.\mvnw.cmd clean package
java -jar target\game-narrator-<版本>.jar
```

## 4. Web前端

进入 `frontend` 目录：

```powershell
npm ci
npm run dev
```

开发服务器默认使用 `http://127.0.0.1:5173`。如果提示端口5173已占用，请关闭旧的Vite进程，或者在 `frontend/vite.config.js` 中修改开发端口。

生产构建：

```powershell
npm run build
```

构建产物会写入后端静态资源目录。`frontend/public` 中的普通脚本只能通过HTML标签引用，不要从Vue源码中直接导入，否则Vite会报告public文件未经过插件转换。

## 5. Windows启动器

构建启动器：

```powershell
dotnet build launcher\GameNarrator.Launcher.csproj -c Release
```

启动器负责检查Java、后端端口和WebView2，然后启动后端并打开应用页面。发布时必须让 `GameNarrator.exe` 与 `app`、`runtime`、`tools` 和 `models` 目录保持在同一级目录，不能只复制EXE。

## 6. Android客户端

首次构建前，在 `android-app/local.properties` 中配置Android SDK路径，例如：

```properties
sdk.dir=D\:\\Android\\Sdk
```

构建调试版：

```powershell
cd android-app
.\gradlew.bat assembleDebug
```

APK输出位置：

```text
android-app\app\build\outputs\apk\debug\app-debug.apk
```

Android客户端需要访问电脑后端。真机不能使用 `127.0.0.1` 连接电脑，请在应用设置中填写电脑局域网地址，例如 `http://192.168.1.20:8081`，并确保Windows防火墙允许8081端口。

## 7. Ollama与模型放到非C盘

先在非系统盘创建模型目录，例如 `G:\GameNarrator\models\ollama`。在启动Ollama前设置：

```powershell
$env:OLLAMA_MODELS='G:\GameNarrator\models\ollama'
ollama serve
```

安装项目使用的视觉模型：

```powershell
ollama pull qwen2.5vl:3b
ollama list
```

模型名称必须与 `ollama list` 完全一致。本地请求不能使用历史记录中的 `qwen-plus` 等云端模型名称，否则会返回HTTP 404。

如需长期保存环境变量，可在Windows“系统属性 → 环境变量”中新增：

```text
变量名：OLLAMA_MODELS
变量值：G:\GameNarrator\models\ollama
```

## 8. Whisper、Piper与FFmpeg

在应用配置中分别设置：

```text
FFmpeg：G:\GameNarrator\tools\ffmpeg\bin\ffmpeg.exe
Whisper：G:\GameNarrator\tools\whisper\Release\whisper-cli.exe
Whisper模型：G:\GameNarrator\models\whisper\ggml-base.bin
Piper：G:\GameNarrator\tools\piper\piper\piper.exe
Piper模型：G:\GameNarrator\models\piper\zh_CN-huayan-medium.onnx
```

完成后在系统诊断页检查依赖状态。黄色通常表示可选能力未启用；红色表示会阻塞对应流程。

## 9. PostgreSQL配置（可选）

本地课程演示可以使用默认H2数据库。需要PostgreSQL时，可使用根目录的 `docker-compose.postgresql.yml`，并配置以下环境变量：

```text
SPRING_PROFILES_ACTIVE=postgresql
SPRING_DATASOURCE_URL=jdbc:postgresql://127.0.0.1:5432/game_narrator
SPRING_DATASOURCE_USERNAME=game_narrator
SPRING_DATASOURCE_PASSWORD=请设置强密码
```

启动后在诊断页确认Flyway迁移为绿色。不要手动删除或修改 `flyway_schema_history`。

## 10. 常见问题

### 端口5173已占用

关闭旧的Vite开发服务器，确认没有重复执行 `npm run dev`。生产便携版不需要启动Vite。

### 本地模型HTTP 404

执行 `ollama list`，确认模型已安装且名称与应用设置一致；同时确认 `ollama serve` 正在运行。

### 页面提示无法导入 `/app.js`

不要在Vue源码中使用 `import '/app.js'`。public目录脚本应由HTML中的 `<script>` 标签加载。

### Android无法连接后端

使用电脑局域网IP，不要使用手机自己的127.0.0.1；检查电脑和手机是否连接同一网络，并允许Windows防火墙访问8081端口。

### 数据库迁移为红色

检查数据库是否创建、账号是否有建表权限以及Flyway历史表是否存在。H2与PostgreSQL配置不能混用。

## 11. 首次验收顺序

1. 启动后端并打开Web首页。
2. 在诊断页确认磁盘、数据库和FFmpeg正常。
3. 启动Ollama并确认 `qwen2.5vl:3b` 可用。
4. 检查Whisper与Piper路径。
5. 导入一个短视频执行完整流程。
6. 检查分镜、脚本、配音、时间线和最终MP4。
7. 在Android端填写电脑地址并查看同一任务。
